# Эмулятор командной строки UNIX-подобной ОС

Практическая работа №3, вариант №3. Консольный эмулятор оболочки с
виртуальной файловой системой (VFS), которая целиком находится в оперативной
памяти.

Реализованы все пять этапов задания:

1. интерактивный REPL, парсер аргументов с кавычками, команды-заглушки;
2. параметры командной строки и стартовые скрипты;
3. VFS из CSV-файла, вложенные каталоги, двоичные данные в Base64;
4. команды `ls`, `cd`, `who`, `tree`, `uname`;
5. команды `touch`, `rmdir` (изменения только в памяти).

Подробный отчёт с примерами работы — в файле [`Pr_3.md`](Pr_3.md).

## Сборка

Требуется CMake 3.16+ и компилятор с поддержкой C++17 (GCC, Clang, MSVC,
MinGW). Проект собирается одинаково на Linux и Windows.

Linux/macOS:

```bash
cmake -S pr_3 -B pr_3/build -DCMAKE_BUILD_TYPE=Release
cmake --build pr_3/build -j
./pr_3/build/bin/emu --vfs pr_3/vfs/demo.csv
```

Windows (Visual Studio):

```bat
cmake -S pr_3 -B pr_3\build
cmake --build pr_3\build --config Release
pr_3\build\bin\Release\emu.exe --vfs pr_3\vfs\demo.csv
```

Windows (MinGW/Ninja) кладёт исполняемый файл в `pr_3\build\bin\emu.exe`.
Готовые скрипты Windows сами ищут `Release\emu.exe`, затем `bin\emu.exe`.

## Параметры командной строки

```
emu [параметры]

--vfs <путь>       путь к CSV-файлу с физическим расположением VFS
--script <путь>    стартовый скрипт с командами эмулятора
-i, --interactive  остаться в интерактивном режиме после скрипта
--debug            отладочный вывод параметров (по умолчанию включён)
--no-debug         отключить отладочный вывод
-h, --help         справка
-V, --version      версия
```

Допустимы обе формы записи: `--vfs путь` и `--vfs=путь`.
При запуске эмулятор печатает все заданные параметры (см. `--no-debug`):

```
$ ./emu --vfs vfs/demo.csv --script scripts/stage3.emu
[config] отладочный вывод параметров запуска:
[config]   путь к VFS:       "vfs/demo.csv"
[config]   стартовый скрипт: "scripts/stage3.emu"
[config]   режим работы:     пакетный (только скрипт)
[config]   отладочный вывод: включён
[config]   версия:           0.5.0
[config]   VFS (абс. путь):  /home/user/pr_3/vfs/demo.csv
[config]   скрипт (абс. путь): /home/user/pr_3/scripts/stage3.emu
[vfs] загружено из "vfs/demo.csv": имя "demo", каталогов 10, файлов 8, объём 418 Б
demo:/$ ...
```

Без `--vfs` используется пустая встроенная VFS с корнем `/` и именем `vfs`.

## Формат CSV для VFS

Источник VFS — обычный CSV-файл, который только читается. Все изменения
хранятся в памяти и никогда не записываются на диск.

Строки-комментарии начинаются с `#`; директива `# vfs: <имя>` задаёт имя VFS,
которое выводится в приглашении. Первая строка данных — заголовок:

```csv
type,name,parent,mode,content,encoding
```

| Поле       | Назначение                                                        |
|------------|-------------------------------------------------------------------|
| `type`     | `dir` или `file`                                                  |
| `name`     | имя элемента; для корня — `/`                                     |
| `parent`   | абсолютный путь родительского каталога (для корня пусто)          |
| `mode`     | права в восьмеричном виде, например `0755` (можно опустить)       |
| `content`  | содержимое файла; для каталога пусто                              |
| `encoding` | `text` (по умолчанию) или `base64` для двоичных данных            |

Вложенность задаётся полем `parent`: каждый элемент ссылается на уже
объявленный каталог, поэтому файл-источник остаётся плоским, а дерево
строится при загрузке. Пример:

```csv
# vfs: demo
type,name,parent,mode,content,encoding
dir,/,,"0755",,
dir,etc,/,"0755",,
file,motd,etc,"0644","Добро пожаловать в эмулятор VFS!","text"
file,logo.bin,etc,"0644","iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg==","base64"
dir,home,/,"0755",,
dir,user,home,"0755",,
dir,docs,home/user,"0755",,
file,notes.txt,home/user/docs,"0644","Заметки: VFS живёт в памяти, на диск ничего не пишется.","text"
```

Особенности парсера CSV: поля в двойных кавычках, запятые и кавычки внутри
полей (удвоение `""`), переводы строк CRLF и BOM. Ошибки загрузки содержат
имя файла и номер строки, например:

```
emu: vfs/bad/duplicate.csv:6: элемент уже существует: /etc/passwd
```

Готовые наборы:

| Файл                | Содержимое                                                      |
|---------------------|-----------------------------------------------------------------|
| `vfs/minimal.csv`   | минимальный: корень и один файл                                 |
| `vfs/multi.csv`     | несколько файлов и каталогов, скрытый файл, файл без расширения  |
| `vfs/demo.csv`      | 4 уровня вложенности, Base64, кириллица, разные права            |
| `vfs/bad/*.csv`     | некорректные файлы для проверки обработки ошибок                 |

## Команды

| Команда                    | Описание                                                         |
|----------------------------|------------------------------------------------------------------|
| `ls [-l] [-a] [путь...]`   | содержимое каталога; `-l` — подробный формат, `-a` — `.` и `..`   |
| `cd [путь]`                | переход; без аргумента или `~` — в `/`, `cd -` — назад             |
| `who`                      | пользователь и терминал текущего сеанса                          |
| `tree [путь]`              | дерево каталогов с итоговым числом каталогов и файлов             |
| `uname [-snrvmoa]`         | сведения о системе                                               |
| `touch <файл...>`          | создать файл в VFS (существующий не изменяется)                   |
| `rmdir <каталог...>`       | удалить пустой каталог; корень и непустые каталоги запрещены      |
| `exit [код]`               | выход с кодом 0..255                                             |
| `help`                     | справка                                                          |

```
demo:/$ ls -la /etc
drwxr-xr-x 4096  .
drwxr-xr-x 4096  ..
-rw-r--r--   70  logo.bin
-rw-r--r--   56  motd
-rw-r--r--   29  passwd
demo:/$ cd /home/user/docs
demo:/home/user/docs$ tree /
/
├── bin
│   └── hello
├── etc
│   ├── logo.bin
...
каталогов: 9, файлов: 8
```

Строка разбирается на аргументы с поддержкой одинарных и двойных кавычек и
экранирования `\`. В стартовых скриптах `#` в начале слова начинает
комментарий.

## Скрипты

Стартовые скрипты эмулятора (`scripts/`):

| Файл             | Назначение                                             |
|------------------|--------------------------------------------------------|
| `stage2.emu`     | параметры, комментарии, кавычки, ошибки                |
| `stage3.emu`     | VFS, обход дерева, ошибки путей                        |
| `stage4.emu`     | все режимы `ls`, `cd`, `who`, `tree`, `uname`          |
| `stage5.emu`     | `touch`, `rmdir`, обработка ошибок                     |
| `startup.emu`    | короткий стартовый скрипт для режима `--interactive`   |


Скрипты реальной ОС:

| Файл                                             | Назначение                                  |
|--------------------------------------------------|---------------------------------------------|
| `scripts/os/linux/check_cli.sh`                  | все параметры командной строки, 15 проверок |
| `scripts/os/linux/vfs_variants.sh`               | три варианта VFS и ошибки CSV, 10 проверок  |
| `scripts/os/linux/demo_stage2.sh` … `demo_stage5.sh` | демонстрация этапов                     |
| `scripts/os/windows/check_cli.bat` и другие      | то же для Windows                           |
| `scripts/run_all.sh` / `run_all.bat`             | полный прогон всех проверок                 |

Запуск (Linux):

```bash
cd pr_3
./scripts/run_all.sh
# [PASS] этап 2: стартовый скрипт
# [PASS] этап 3: VFS и команды
# [PASS] этап 4: основные команды
# [PASS] этап 5: touch и rmdir
# [PASS] параметры командной строки
# [PASS] варианты VFS
#
# Итого: успешно 6, провалено 0
```

Отдельные проверки: `bash scripts/os/linux/check_cli.sh` (15 сценариев
параметров) и `bash scripts/os/linux/vfs_variants.sh` (10 сценариев VFS).

## Ограничения модели

* содержимое файла в CSV занимает одну строку (многострочный текст не
  поддерживается — это сознательное упрощение формата);
* время изменения файлов не моделируется, поэтому повторный `touch`
  существующего файла — успешная операция без видимых изменений;
* права доступа отображаются, но не проверяются при операциях;
* имена и содержимое обрабатываются как байтовые строки UTF-8;
* физический диск не изменяется: CSV только читается, все мутации живут
  в памяти до завершения процесса.
