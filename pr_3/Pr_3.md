# Практика 3

Вариант №3: эмулятор командной строки UNIX-подобной ОС с виртуальной файловой
системой в оперативной памяти. Все пять этапов реализованы в одном дереве
`pr_3/`, работа разбита на три коммита: каркас и конфигурация (этапы 1–2),
VFS и основные команды (этапы 3–4), дополнительные команды и оформление
(этап 5).

Инструменты: C++17, CMake 3.16+, GCC 12 (Linux), MSVC/MinGW (Windows).
Внешних библиотек нет.

## Архитектура

```
pr_3/
├── CMakeLists.txt          сборка под Linux и Windows
├── include/emu/
│   ├── base64.hpp          кодирование/декодирование Base64
│   ├── config.hpp          параметры командной строки
│   ├── csv.hpp             разбор CSV с кавычками
│   ├── lexer.hpp           разбор строки на аргументы
│   ├── path.hpp            нормализация путей VFS
│   ├── shell.hpp           REPL, скрипты, команды
│   ├── vfs.hpp             узлы и дерево VFS
│   └── version.hpp         версия и описание этапа
├── src/                    реализация перечисленных модулей + main.cpp
├── vfs/                    CSV-наборы VFS и файлы с ошибками
├── scripts/                стартовые скрипты и скрипты реальной ОС
├── README.md               краткая документация
└── Pr_3.md                 этот отчёт
```

Ключевые решения:

* оболочка не знает, откуда взялась VFS: `Vfs` загружается один раз в
  `main` и передаётся в `Shell` по ссылке;
* все команды возвращают код завершения (0 — успех), который используется
  в скриптах и при выходе;
* ошибки печатаются в `stderr`, результаты команд — в `stdout`;
* ни одна операция не пишет на диск: CSV только читается, изменения дерева
  живут в памяти процесса;
* переносимый код: работа с консолью Windows (UTF-8, `CommandLineToArgvW`)
  спрятана за `#ifdef _WIN32`, CMake добавляет `/utf-8 /W4` для MSVC и
  `-Wall -Wextra -Wpedantic` для GCC/Clang.

Сборка:

```bash
cmake -S pr_3 -B pr_3/build -DCMAKE_BUILD_TYPE=Release
cmake --build pr_3/build -j
```

## Этап 1. REPL

### Что сделано

* консольный интерфейс: цикл «приглашение — ввод — разбор — выполнение»;
* приглашение содержит имя VFS: `vfs:/$ `;
* парсер аргументов поддерживает одинарные и двойные кавычки, экранирование
  `\` и сообщает позицию ошибки;
* команды-заглушки `ls` и `cd` печатают своё имя и все аргументы;
* команда `exit [код]` с проверкой кода 0..255, справка `help`;
* при ошибке разбора строка не выполняется, эмулятор продолжает работу.

### Демонстрация

```
$ ./build/bin/emu
Эмулятор командной строки UNIX-подобной ОС, этап 1.
Введите help для списка команд, exit — для выхода.
vfs:/$ ls /
ls: заглушка, аргументов: 1
  аргумент 1: "/"
vfs:/$ cd "/home/user dir"
cd: заглушка, аргументов: 1
  аргумент 1: "/home/user dir"
vfs:/$ ls -l "файл с пробелами" 'ещё аргумент'
ls: заглушка, аргументов: 3
  аргумент 1: "-l"
  аргумент 2: "файл с пробелами"
  аргумент 3: "ещё аргумент"
vfs:/$ cd
cd: заглушка, аргументов: 0
vfs:/$ ls "незакрытая
emu: ошибка разбора строки: не закрыта двойная кавычка (позиция 4)
vfs:/$ abrakadabra
emu: команда не найдена: abrakadabra (для списка команд введите help)
vfs:/$ exit 3
[процесс завершился с кодом 3]
```

Проверка кода возврата:

```
$ printf 'exit 3\n' | ./build/bin/emu > /dev/null; echo "код: $?"
код: 3
$ printf 'exit abc\n' | ./build/bin/emu
vfs:/$ exit: неверный код завершения: abc (ожидается целое число 0..255)
```

## Этап 2. Конфигурация

### Что сделано

Параметры командной строки (обе формы — `--vfs путь` и `--vfs=путь`):

| Параметр           | Назначение                                   |
|--------------------|----------------------------------------------|
| `--vfs <путь>`     | путь к физическому расположению VFS          |
| `--script <путь>`  | путь к стартовому скрипту                    |
| `--interactive`    | остаться в REPL после выполнения скрипта     |
| `--no-debug`       | выключить отладочный вывод параметров        |
| `--help`, `--version` | справка и версия                          |

При запуске печатаются все заданные параметры, включая абсолютные пути,
режим работы и версию. Ошибки параметров завершают программу с кодом 2,
ошибка открытия скрипта — с кодом 1.

Стартовый скрипт:

* комментарии начинаются с `#` и могут занимать строку целиком или её конец;
* пустые строки и комментарии не отображаются;
* каждая выполняемая строка печатается вместе с приглашением, затем вывод
  команды — получается диалог, как при ручном вводе;
* ошибка разбора или команды не останавливает скрипт, но печатается с именем
  файла и номером строки:

```
[script] scripts/stage2.emu:23: ошибка разбора: не закрыта двойная кавычка (позиция 4)
[script] scripts/stage2.emu:26: команда завершилась с кодом 127
```

## Этап 3. VFS

### Формат CSV и представление вложенности

VFS загружается из CSV-файла, который только читается. Заголовок:

```csv
type,name,parent,mode,content,encoding
```

Каждая строка описывает один узел. Вложенность представлена **ссылкой на
родительский каталог** в поле `parent`: файл-источник остаётся плоским, а
дерево строится при загрузке последовательным добавлением узлов. Это удобнее
полного пути (`/home/user/docs/notes.txt`) тем, что не нужно повторять
родительские компоненты, и проще проверять: родитель обязан быть объявлен
раньше, дубликаты имён и циклы исключены по построению.

Пример `vfs/demo.csv` (фрагмент):

```csv
# vfs: demo
type,name,parent,mode,content,encoding
dir,/,,"0755",,
dir,etc,/,"0755",,
file,passwd,etc,"0644","root:x:0:0:root:/root:/bin/sh","text"
file,logo.bin,etc,"0644","iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAYAAAAfFcSJAAAADUlEQVR42mP8z8BQDwAEhQGAhKmMIQAAAABJRU5ErkJggg==","base64"
dir,home,/,"0755",,
dir,user,home,"0755",,
dir,docs,home/user,"0755",,
file,notes.txt,home/user/docs,"0644","Заметки: VFS живёт в памяти, на диск ничего не пишется.","text"
dir,tmp,/,"1777",,
dir,empty,tmp,"0755",,
file,кириллица.txt,tmp,"0644","Файл с именем на кириллице","text"
```

Двоичные данные (`logo.bin`, 1×1 PNG, 70 байт) хранятся в Base64 и
декодируются при загрузке. При ошибке декодирования загрузка прекращается
с указанием строки.

Загрузчик проверяет:

* наличие заголовка и допустимость типа (`dir`/`file`);
* восьмеричный формат прав, значения по умолчанию (`0755`/`0644`);
* корректность CSV: кавычки, запятые внутри полей, удвоение `""`, CRLF, BOM;
* допустимость имён (не пусто, не `.`/`..`, без разделителей);
* существование и тип родителя, отсутствие дубликатов;
* корректность Base64 и известность кодировки.

Примеры диагностики:

```
emu: vfs/bad/duplicate.csv:6: элемент уже существует: /etc/passwd
emu: vfs/bad/unknown-parent.csv:4: родительский каталог не найден: /нет-такого-каталога
emu: vfs/bad/bad-base64.csv:4: ошибка Base64: длина Base64 должна быть кратна 4
emu: vfs/bad/bad-quotes.csv:4: не закрыта кавычка в поле CSV
emu: vfs/bad/no-header.csv:1: первая строка данных должна быть заголовком ...
```

### Дерево и команды

Узлы хранятся в `std::map`, поэтому вывод всегда отсортирован. На этом этапе
`ls` и `cd` уже работают с VFS, а приглашение показывает текущий каталог.

```
$ ./build/bin/emu --vfs vfs/demo.csv
[vfs] загружено из "vfs/demo.csv": имя "demo", каталогов 10, файлов 8, объём 418 Б
demo:/$ ls /
bin  etc  home  tmp  var
demo:/$ cd /home/user/docs
demo:/home/user/docs$ ls
notes.txt
demo:/home/user/docs$ cd ../..
demo:/home$ ls
user
demo:/$ ls /нет-такого
ls: /нет-такого: нет такого файла или каталога
demo:/$ cd /etc/passwd
cd: /etc/passwd: не каталог
```

Стартовый скрипт `scripts/stage3.emu` обходит четыре уровня, проверяет
`ls`/`cd`, цитирование, ошибки путей, ошибку разбора и неизвестную команду.

Три набора VFS и проверки ошибок:

```
$ ./build/bin/emu --vfs vfs/minimal.csv
minimal:/$ ls /
hello.txt

$ ./build/bin/emu --vfs vfs/multi.csv
multi:/$ ls -a /
.  ..  .hidden  README  alpha.txt  beta.txt  etc  tmp

$ ./build/bin/emu --vfs vfs/demo.csv --script scripts/stage3.emu
...
$ bash scripts/os/linux/vfs_variants.sh
Итого: успешно 10, провалено 0
```

Итого на этапе 3: `minimal.csv` (1 файл), `multi.csv` (несколько файлов и
каталогов), `demo.csv` (4 уровня вложенности), плюс `vfs/bad/*` для ошибок.
CSV-файл и физический диск при этом не изменяются — это проверяется на
этапе 5 отдельно.

## Этап 4. Основные команды

### ls

* `ls [путь...]` — список имён; несколько путей выводятся с заголовками;
* `-l` — подробный формат: тип и права, размер, имя;
* `-a` — добавляет `.` и `..`;
* `--` завершает список опций;
* неизвестная опция — код 2; несуществующий путь — код 1, остальные операнды
  всё равно обрабатываются (частичная ошибка).

```
demo:/$ ls -l /
drwxr-xr-x 4096  bin
drwxr-xr-x 4096  etc
drwxr-xr-x 4096  home
drwxrwxrwt 4096  tmp
drwxr-xr-x 4096  var
demo:/$ ls -la /etc
drwxr-xr-x 4096  .
drwxr-xr-x 4096  ..
-rw-r--r--   70  logo.bin
-rw-r--r--   56  motd
-rw-r--r--   29  passwd
demo:/$ ls /etc /tmp
/etc:
logo.bin  motd  passwd

/tmp:
empty  кириллица.txt
demo:/$ ls -l /нет-такого /etc
ls: /нет-такого: нет такого файла или каталога
/etc:
-rw-r--r-- 70  logo.bin
-rw-r--r-- 56  motd
-rw-r--r-- 29  passwd
[код возврата: 1]
```

Права преобразуются в символьный вид, включая специальные биты: у `/tmp`
режим `1777`, поэтому выводится `drwxrwxrwt`.

### cd

* без аргумента и `~` — переход в `/`;
* `cd -` — возврат в предыдущий каталог (новый путь печатается);
* проверяются существование и тип узла, лишние аргументы запрещены.

### who, tree, uname

```
demo:/$ who
emu      tty0     2026-10-28 08:25
demo:/$ tree /home
/home
└── user
    ├── docs
    │   └── notes.txt
    └── readme.md

каталогов: 2, файлов: 2
demo:/$ uname
EmuVFS
demo:/$ uname -a
EmuVFS demo 1.0.0 #1 SMP emu 0.5.0 x86_64 EmuOS
demo:/$ uname -sn
EmuVFS demo
```

`uname` поддерживает `-s` (имя системы), `-n` (имя VFS), `-r` (релиз),
`-v` (версия), `-m` (архитектура), `-o` (ОС), `-a` (всё), а также их
комбинации. `tree` печатает дерево псевдографикой и итоговую статистику,
`who` — пользователя и время сеанса.

Обработка ошибок:

```
demo:/$ ls -z
ls: недопустимая опция -- 'z'
demo:/$ cd /etc /tmp
cd: слишком много аргументов
demo:/$ tree /нет-такого
tree: /нет-такого: нет такого файла или каталога
demo:/$ uname -z
uname: недопустимая опция -- 'z'
demo:/$ who лишний-аргумент
who: слишком много аргументов
```

Стартовый скрипт `scripts/stage4.emu` проверяет все перечисленные режимы,
включая частичные ошибки и коды возврата. Скрипт ОС
`scripts/os/linux/demo_stage4.sh` дополнительно прогоняет все параметры
командной строки и три набора VFS.

## Этап 5. Дополнительные команды

### touch

* создаёт пустой файл в указанном каталоге VFS;
* принимает несколько операндов;
* повторный вызов для существующего файла успешен (время в модели не
  хранится);
* ошибки: нет родительского каталога, родитель — файл, нет операндов,
  неизвестная опция.

### rmdir

* удаляет только пустые каталоги;
* ошибки: файл вместо каталога, несуществующий путь, непустой каталог,
  попытка удалить корень, нет операндов;
* несколько операндов обрабатываются последовательно, итоговый код 1, если
  хотя бы один не удалён.

```
demo:/$ touch /home/user/new.txt
demo:/$ touch "/tmp/файл с пробелом.txt"
demo:/$ touch /home/user/docs/a.txt /home/user/docs/b.txt
demo:/$ ls -l /home/user/docs
-rw-r--r--  0  a.txt
-rw-r--r--  0  b.txt
-rw-r--r-- 95  notes.txt
demo:/$ touch /home/user/new.txt
demo:/$ rmdir /tmp/empty
demo:/$ ls -la /tmp
drwxrwxrwt 4096  .
drwxr-xr-x 4096  ..
-rw-r--r--   48  кириллица.txt
-rw-r--r--    0  файл с пробелом.txt
demo:/$ touch /нет-такого/файл.txt
touch: /нет-такого/файл.txt: нет такого файла или каталога
demo:/$ touch /etc/passwd/внутри
touch: /etc/passwd/внутри: родительский путь не является каталогом
demo:/$ rmdir /home/user/docs
rmdir: /home/user/docs: каталог не пуст

demo:/$ rmdir /tmp/empty /tmp

rmdir: /tmp: каталог не пуст
```

### Доказательство «только в памяти»

Скрипт `scripts/os/linux/demo_stage5.sh` считает контрольную сумму CSV до и
после запуска, затем проверяет отсутствие созданных файлов на диске:

```
контрольная сумма CSV до запуска:    733860207 1238
контрольная сумма CSV после запуска: 733860207 1238
  [PASS] CSV-файл VFS не изменён
  [PASS] созданные в VFS файлы отсутствуют на физическом диске
```

Для Windows то же самое делает `scripts/os/windows/demo_stage5.bat`
(копия файла и `fc /b`).

## Обработка ошибок: сводка

| Ситуация                          | Сообщение                                         | Код |
|-----------------------------------|---------------------------------------------------|-----|
| Неизвестный параметр              | `emu: неизвестный параметр: --bogus`              | 2   |
| Параметр без значения             | `emu: параметр --vfs требует значения`            | 2   |
| Нет стартового скрипта            | `emu: не удалось открыть стартовый скрипт: ...`   | 1   |
| Ошибка CSV                        | `emu: <файл>:<строка>: <причина>`                 | 1   |
| Неизвестная команда               | `emu: команда не найдена: ...`                    | 127 |
| Нет пути                          | `ls: <путь>: нет такого файла или каталога`       | 1   |
| cd в файл                         | `cd: <путь>: не каталог`                          | 1   |
| Ошибка разбора строки             | `emu: ошибка разбора строки: ... (позиция N)`     | 2   |
| Ошибка в скрипте                  | `[script] <файл>:<строка>: ...`                   | —   |

## Ограничения

* содержимое файла в CSV занимает одну строку — многострочный текст не
  поддерживается;
* время изменения файлов не моделируется (`touch` существующего файла —
  успешная операция без видимых изменений);
* права доступа отображаются, но не проверяются при операциях;
* пользователи и группы не моделируются, `who` показывает один сеанс;
* Windows-скрипты `.bat` и переносимость кода обеспечены, но сборка в этой
  среде проверена компилятором GCC на Linux.

## Вывод

Получен работающий эмулятор командной строки UNIX-подобной ОС: интерактивный
REPL и пакетный режим со стартовыми скриптами, настраиваемый через параметры
командной строки, с виртуальной файловой системой из CSV в оперативной
памяти, командами `ls`, `cd`, `who`, `tree`, `uname`, `touch`, `rmdir` и
единообразной обработкой ошибок. Проект собирается CMake на Linux и Windows,
работа разбита на три последовательных коммита.
